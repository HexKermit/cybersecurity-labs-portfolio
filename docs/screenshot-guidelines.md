# Screenshot Guidelines

This document defines the screenshot and evidence standards used throughout this cybersecurity portfolio.

The objective is to maintain professional, organized, and technically meaningful documentation across all lab repositories.

# General Screenshot Standards

Screenshots should:

* Be clear and readable
* Focus on relevant technical evidence
* Avoid unnecessary desktop clutter
* Maintain professional presentation
* Support findings and analysis within the report

# Sensitive Information

The following information should never appear in screenshots:

* Personal email addresses
* Personal IP addresses
* API keys
* Passwords
* Authentication tokens
* Sensitive browser bookmarks
* Personal files or folders
* Personal notifications

If necessary, sensitive information should be blurred or removed before uploading.

# Recommended Screenshot Types

Useful screenshots include:

* Splunk dashboards
* IDS alerts
* Wireshark packet captures
* Vulnerability scan results
* Firewall configurations
* Active Directory configurations
* Security logs
* Command outputs
* Detection results
* Network traffic analysis

# Offensive Security Documentation

Offensive security screenshots should:

* Remain professional and technical
* Focus on vulnerability understanding
* Emphasize defensive learning outcomes
* Avoid unnecessary exploit glorification
* Clearly indicate authorized lab environments

# File Naming Standards

Recommended screenshot naming format:

* scan-results-01.png
* suspicious-traffic-analysis.png
* splunk-alert-correlation.png
* firewall-rule-analysis.png
* packet-analysis-http-traffic.png

Avoid random file names such as:

* image1.png
* screenshot-final-final2.png
* test.png

# Screenshot Organization

Each lab repository should organize screenshots inside a dedicated folder.

Example:

screenshots/
├── detection-results/
├── traffic-analysis/
├── findings/
├── alerts/
└── configurations/

# Annotation Recommendations

When appropriate, screenshots may include:

* Highlighted indicators
* Arrows or boxes
* Brief annotations
* IOC highlights
* Important log entries

Annotations should remain clean and professional.

# Technical Documentation Quality

Screenshots should support:

* Technical analysis
* Findings validation
* Investigation workflows
* Security observations
* Detection methodologies

Screenshots should not be used as replacements for written explanations.

# Portfolio Consistency

Maintaining consistent screenshot quality across repositories improves:

* Professional appearance
* Documentation readability
* Recruiter perception
* Technical credibility

Consistent documentation standards help present the portfolio as a structured and mature technical project rather than a collection of random lab screenshots.
